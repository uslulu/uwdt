# Аудит UWDT на macOS arm64

## Повторный проход в окне macOS

В отдельном приложении Wails с WKWebView проверены пустое окно, добавление синтетического VLESS-сервера клавишей Enter, ошибка неполной ссылки, реальная ошибка загрузки подписки с loopback, включение и отключение сессии, сворачивание и возврат. В разделе правил сохранён 127.0.0.1/32. Проверка адреса показала правило и интерфейс lo0. Использовались настоящий мост, отдельный каталог, тестовое хранилище ключа и подмена операции запуска Xray с настройкой сети. Передачу пакетов через VPN и восстановление после изменения системного DNS этот проход не измеряет.

Исправлены фокус ввода и Escape, ошибки теперь остаются в форме. До получения входящего трафика главный экран показывает «Туннель включён». Для «Подключено» требуются активный канал и свежий прирост счётчика приёма. Ошибка восстановления маршрутов имеет отдельный заголовок. Добавление другого сервера во время сессии сохраняет отображение используемого сервера.

Для чистой сборки создан новый каталог из существующих tracked и untracked файлов по git ls-files. Среди исходников присутствовали Rust AEAD и встроенные ресурсы. frontend/dist, node_modules, build/bin и Cargo target отсутствовали на старте. Выполнены штатная сборка Wails darwin/arm64 и Windows production amd64. Для повторения из удалённой ветки понадобится включить текущие неотслеживаемые исходники в коммит. Frontend — 71 тест в девяти файлах, TypeScript и ESLint прошли. Go vet и race-тесты прошли в корневом модуле и core.

Ниже описаны ветви кода. Успешное снятие маршрутов UWDT позволяет ОС выбрать оставшийся выход, в том числе другой VPN. Конкретный путь проверяется действием «Проверить адрес».

| Платформа | IPv4 | IPv6 и DNS |

| macOS | WG учитывает AllowedIPs, полный IPv4 и Xray используют два /1. Watchdog запрашивает снятие и возврат маршрутов через helper. | Правила исключений охватывают IPv4. ### Дополнительные дефекты за пределами первоначального разбора macOS

- На Windows WireGuard меняет метрику физического default route на 9999 и записывает 35 при отключении. Исходное значение не считывается. Сохранять исходную запись и восстанавливать её, если ей всё ещё владеет текущая сессия. См. `backend/wg.go`, функции applyWindows и teardownWindowsLocked.
- В Windows bulkRoutes считает уже существующий маршрут успешным. При отключении deleteRoutes удаляет совпадения по префиксу и шлюзу. Хранить интерфейс и список записей, действительно созданных приложением. Тестировать с заранее существующим совпадающим маршрутом. См. `backend/routes_windows.go`.
- В Linux SetTunnelRoutes возвращает успех без изменения таблицы, в Windows ошибки команд смены маршрутов игнорируются. Watchdog опирается на результат при сообщении о восстановлении. Возвращать фактическое состояние либо явный признак отсутствия поддержки.
- Переименование профиля использует отображаемое имя для сравнения и очищенное имя для пути. Переименование «Дом» в «Дом!» записывает и удаляет один файл. Неудачное обычное удаление тоже скрыто от UI. Использовать стабильный ID для пути, перенести rename в backend и проверить коллизии и миграцию существующих профилей. См. `frontend/src/modals/Edit-server.tsx` и `backend/store.go`.
- Несколько setter-методов выполняют независимые операции чтение–изменение–запись одного config.json. Конкурирующие вызовы могут потерять изменения. Уникальный временный файл решает конфликт имён, но для изменения настроек нужна также сериализация всей операции. См. `backend/app.go` и `backend/store.go`.

## Архитектура

1. Точка входа macOS размещает `frontend/dist` в бинарнике, открывает окно Wails и привязывает методы `backend.App` к WebView (`main_darwin.go:17–25,33–48`).
2. React вызывает сгенерированные функции Wails. Backend отправляет события подключения, статистики, логов и обновлений, а React раскладывает их по локальным хранилищам (`frontend/wailsjs/go/backend/App.js:5`, `backend/app.go:234–235`, `frontend/src/App.tsx:37–90`).
3. `App` создаёт `Store` и `Bridge`. Bridge выбирает VK TURN/WireGuard либо Xray/VLESS из подписки (`backend/app.go:23–40,197–209`, `backend/bridge.go:38–100,159–214`).
4. `core` — отдельный Go-модуль. Он поднимает UDP на loopback, запускает диспетчер и группы воркеров с VK TURN credentials (`go.mod:93`, `core/go.mod:1–15`, `core/main.go:248–294,366–371`, `core/worker_group.go:43–83`).
5. Воркеры получают TURN allocation и permission, поднимают DTLS к peer, запрашивают конфигурацию WireGuard и передают её Bridge (`core/session.go:240–288,447–467,503–531`, `core/main.go:296–314`, `backend/bridge.go:358–379`).
6. На macOS тот же исполняемый файл в режиме root-helper создаёт `utun` и передаёт FD через Unix-сокет. Основной процесс поднимает userspace WireGuard и применяет UAPI (`backend/wg_darwin.go:76–103,247–294,674–687,768–769`).
7. По сети вложенность исходящего пакета такова: `utun → WireGuard → UDP loopback → dispatcher/worker → DTLS → RTP-подобная обёртка ChaCha20-Poly1305 → TURN relay`. Обёртка шифрует запись DTLS. Приём проходит обратным путём (`core/dispatcher.go:106–173,177–199`, `core/session.go:322–335,356–424,550–613`, `core/obfs.go:93–135,151–187`).
8. Xray использует тот же механизм создания `utun` и исключений. Трафик подписки передаётся через VLESS, с отдельными настройками транспорта и маршрутизации Xray (`backend/wg_darwin.go:135–162`, `backend/xray.go:56–100,260–290`).
9. Вместо замены IPv4 default helper ставит две половины `/1` для полного туннеля. Прямые маршруты включают адреса транспортных серверов, VK, прежние DNS и пользовательские исключения (`backend/wg_darwin.go:65–76,219–245,716–763`).
10. Исключения поддерживают IPv4, CIDR, домены и ASN. Первое применение берёт кэши. Фоновый резолв и RIPE дополняют список, затем helper получает разницу CIDR (`backend/excludes.go:40–86,113–153,359–395,408–427`, `backend/wg_darwin.go:354–396`).
11. «Россия напрямую» добавляет 8 655 IPv4-префиксов из встроенного снимка или дискового кэша. RIPE обновляет просроченный кэш, агрегируя сети. Helper устанавливает пользовательские префиксы через AF_ROUTE (`backend/ru_ipv4.txt:1`, `backend/russia.go:23–29,64–128,132–175`, `backend/wg_darwin.go:747–755,855–884`).
12. Для полного WireGuard и Xray helper меняет DNS основной физической службы, если DNS не обслуживает другой `utun`. DNS возвращается при остановке или снятии маршрутов. VK watchdog переустанавливает маршруты после восстановления каналов (`backend/wg_darwin.go:106–115,150–152,167–175,777–825`, `backend/dns_darwin.go:53–103`, `backend/watchdog.go:74–128`).
13. Vite/TypeScript собирает UI, скрипт сверяет отпечаток входов/выходов, CI отдельно собирает macOS arm64 и Windows. Установщик обновлений проверяет SHA-256, распаковывает сборку и заменяет bundle (`frontend/package.json:6–12`, `scripts/prepare-frontend.mjs:8–40`, `.github/workflows/build.yml:34–77`, `backend/selfupdate.go:54–89,211–238`, `backend/selfupdate_darwin.go:25–61`).

- Покрыты парсинг конфигов и UAPI, нормализация исключений, агрегация сетей на малых наборах, RTP roundtrip и профиль, открытие/закрытие Bridge в простых состояниях (`tests/wg_test.go:16,242`, `tests/excludes_test.go:11–66`, `tests/russia_test.go:12–24`, `tests/obfs_test.go:67–79`, `tests/bridge_test.go:32–116`). - Тесты defaults Bridge вызывают Connect, но игнорируют результат и не проверяют фактические worker/deviceID настройки (`tests/bridge_test.go:124–170`). Race-прогон обнаружил проблему даже с такими проверками.
- У `core` есть тесты allocation gate, пометок сетевых ошибок, сброса живых сессий и выбора TURN (`core/allocation_gate_test.go:12,49`, `core/session_net_test.go:13,32`, `core/worker_group_test.go:5–40`). В CI обычный Go-прогон ограничивается `backend` и `tests`, без отдельного race и тестов вложенного модуля (`.github/workflows/build.yml:38–42,58–77`).
- Недостающие проверки: установка/откат маршрутов при частичном отказе helper, IPv6 и DNS при сне, смена Wi-Fi и сосуществование с Cisco, устаревший refresh после reconnect, нагрузка с переполненными очередями, завершение капчи и обновление bundle с откатом. Код путей указан в № 2–7, № 10 и таблице дополнительных находок. Тест DNS на macOS покрывает парсинг службы, update-тесты покрывают SHA и выбор релиза (`backend/dns_darwin_test.go:5`, `backend/selfupdate_test.go:16–49`, `backend/update_platform_test.go:11–48`).
- Frontend тестирует хранилища и импорт ссылок (`frontend/src/__tests__/serverStore.test.ts:9`, `frontend/src/__tests__/wdttLink.test.ts:7`, `frontend/src/__tests__/tunnelStore.test.ts:6`). Доставку Wails-событий, реакцию окна на деградацию и подключение через UI нужно проверять отдельно (`frontend/src/App.tsx:37–90`).

## Что нельзя трогать

- WireGuard UAPI, формат команд выдачи конфигурации, DTLS/RTP-инкапсуляцию, nonce, KDF и AEAD без проверки совместимости с сервером и roundtrip в обоих направлениях (`backend/wg_darwin.go:92–103`, `core/protocol.go:10–55`, `core/obfs.go:73–187`, `core/wrap.go:16–30`).
- Порядок установки исключений транспортного канала, туннельных маршрутов и DNS без тестов симметричного отката, сна и соседнего VPN (`backend/wg_darwin.go:716–825`, `backend/dns_darwin.go:53–98`). Исключения RIPE должны сохранять множество охваченных адресов при любой оптимизации (`backend/russia.go:132–175`).
- Протокол передачи utun FD и жизненный цикл helper требуют проверки границ привилегий (`backend/wg_darwin.go:247–294,454–503,647–668,768–769`). Сохранить идентификатор релизного bundle для доступа к существующему WebView storage (`build/darwin/Info.plist:6–17`).

## Требует решения человека

- Политика приватности при обрыве и сне. Определить, когда разрешено восстанавливать прямой выход, что делать с IPv6 и допустимы ли публичные DNS для имён, заданных как исключения (№ 2, № 7).
- Доверенная идентичность издателя и совместимость с текущими релизами, сроки миграции локальных секретов, правила включения приватных данных в диагностический отчёт (№ 5–6, `backend/report.go:21–50`).
- Стенд для воспроизводимого сценария с WireGuard/VK TURN, Xray, отключением канала и Cisco. Согласовать VPN-профиль, права helper, профиль трафика, сетевые интерфейсы и интервалы измерений ([PERF.md](PERF.md)).

## Чего не удалось проверить и почему

- Go 1.26, staticcheck и govulncheck отсутствовали среди проверенных локальных инструментов. Запуски Go относятся к 1.27.1.
- Живые тесты Xray и обновления требуют переменных `UWDT_LIVE_SUB` и `UWDT_LIVE_UPDATE_URL` с `UWDT_LIVE_UPDATE_SHA`. Они пропущены (`tests/xray_live_test.go:24–27,73–76,103–106`, `backend/selfupdate_test.go:54–58`). Тесты Linux-автозапуска пропущены на macOS (`tests/autostart_test.go:13–15`).
- Динамику root-helper, реальный обход трафика/IPv6/DNS, профиль под нагрузкой и поведение Windows UAC/Linux sudoers не проверяли. Статический анализ показывает пути и условия, но не факт утечки на этой машине.
- Экспериментальный `uwdt_rust` исключён из штатных проверок: он требует отдельной библиотеки `rust-aead/target/release/libuwdt_aead.a`, отсутствовавшей в тестовой копии (`core/session_aead_rust.go:1–6`). Сравнение Go/Rust и протокольная совместимость на стенде не измерялись.
